# 2.2. Типы данных и преобразование столбцов в `pandas`

## Цель лекции

На этой лекции мы разберём, как `pandas` хранит типы данных в таблице и как их преобразовывать для анализа. Основные вопросы темы:

- как определить типы столбцов;
- чем отличаются `object`, `int64`, `datetime64`, `category`;
- как переводить данные в строковый, числовой и временной формат;
- как обрабатывать ошибки преобразования;
- когда имеет смысл использовать категориальный тип.

Все примеры построены по коду из Colab-ноутбука с датасетом `best-selling-gameboy.csv`.

## 1. Загрузка данных

```python
import pandas as pd

df_gameboy = pd.read_csv('./best-selling-gameboy.csv')
df_gameboy
```

После загрузки получаем таблицу из `66` строк и `6` столбцов:

- `Game`;
- `Developer(s)`;
- `Publisher`;
- `Platform`;
- `Release date`;
- `Sales`.

Примеры строк показывают, что в таблице хранятся сведения о популярных играх для `Game Boy` и `Game Boy Color`, включая дату выхода и продажи.

## 2. Первичная проверка типов данных

### 2.1. Метод `info()`

```python
df_gameboy.info()
```

`info()` показывает:

- число строк;
- число непустых значений;
- тип каждого столбца;
- объём памяти.

По выводу из ноутбука:

- `Sales` имеет тип `int64`;
- остальные пять столбцов имеют тип `object`.

Это очень типичная ситуация при чтении CSV: числа распознаются как числа, а строки и даты часто сначала читаются как `object`.

### 2.2. Атрибут `dtypes`

```python
df_gameboy.dtypes
```

`dtypes` возвращает тип каждого столбца в компактной форме:

```python
Game            object
Developer(s)    object
Publisher       object
Platform        object
Release date    object
Sales            int64
```

### Практический смысл

Перед анализом почти всегда нужно проверить, соответствуют ли типы содержимому столбцов. Например:

- продажи должны быть числом;
- дата выхода должна быть датой;
- платформа и издатель часто удобнее хранить как категории.

## 3. Преобразование в строковый тип

### 3.1. Метод `astype()`

```python
df_gameboy['sales_str'] = df_gameboy['Sales'].astype('str')
df_gameboy
```

### Что делает метод

`astype()` приводит столбец к указанному типу.

В этом примере числовой столбец `Sales` преобразуется в строковый столбец `sales_str`.

### Зачем это может понадобиться

Преобразование в строку полезно, если:

- нужно выполнить текстовую обработку значений;
- требуется объединять числа с текстом;
- данные пришли в неправильном формате и их нужно сначала очистить.

### Важное следствие

После преобразования значения внешне похожи на числа, но математические операции с таким столбцом уже будут затруднены, потому что тип стал строковым.

## 4. Ошибки в данных и нечисловые значения

В ноутбуке специально создаётся проблема:

```python
df_gameboy.loc[0, 'sales_str'] = 'abc'
df_gameboy['sales_str']
```

Теперь в столбце `sales_str` смешаны:

- строки, похожие на числа;
- строка `'abc'`, которая числом не является.

### Зачем нужен такой пример

В реальных данных подобные ситуации встречаются постоянно:

- опечатки;
- служебные символы;
- текст вместо числа;
- пропуски, записанные строками.

Именно поэтому аналитик должен уметь безопасно переводить столбцы обратно в числа.

## 5. Преобразование в числовой тип

### 5.1. `pd.to_numeric(..., errors='coerce')`

```python
pd.to_numeric(df_gameboy['sales_str'], errors='coerce')
```

### Что делает метод

`pd.to_numeric()` пытается преобразовать значения в числа.

Параметр `errors='coerce'` означает:

- корректные значения перевести в число;
- некорректные заменить на `NaN`.

### Что видно в примере

Строка `'abc'` превращается в `NaN`, а остальные значения успешно становятся числами. Итоговый тип результата:

```python
float64
```

### Почему получился `float64`

`NaN` хранится как специальное числовое значение с плавающей точкой, поэтому вся серия становится вещественной.

### Когда этот режим полезен

`errors='coerce'` удобен, когда нужно:

- найти ошибочные значения;
- очистить столбец;
- затем посчитать количество пропусков или удалить проблемные строки.

### 5.2. `pd.to_numeric(..., errors='ignore')`

```python
pd.to_numeric(df_gameboy['sales_str'], errors='ignore')
```

В этом режиме некорректные данные не ломают преобразование, но и сам столбец фактически остаётся без изменений.

Результат в примере сохраняет тип:

```python
object
```

### Смысл режима

`errors='ignore'` не исправляет проблему, а лишь позволяет избежать исключения. Для очистки данных чаще полезнее `coerce`.

## 6. Проверка типов после промежуточных преобразований

```python
df_gameboy.dtypes
```

После добавления `sales_str` и попыток преобразования без присваивания исходная таблица содержит:

- `Sales` как `int64`;
- `sales_str` как `object`.

### Важный вывод

Вызовы вида:

```python
pd.to_numeric(df_gameboy['sales_str'], errors='coerce')
```

не изменяют таблицу сами по себе. Они возвращают новый объект. Чтобы реально поменять столбец, нужно присваивание:

```python
df_gameboy['sales_str'] = pd.to_numeric(df_gameboy['sales_str'], errors='coerce')
```

Это один из ключевых методических моментов темы.

## 7. Преобразование строк в даты

### 7.1. Метод `pd.to_datetime()`

```python
pd.to_datetime(df_gameboy['Release date'], errors='coerce')
```

### Что делает метод

`pd.to_datetime()` преобразует строки в значения даты и времени.

В ноутбуке столбец `Release date` успешно превращается в тип:

```python
datetime64[ns]
```

### Параметр `errors='coerce'`

Он работает по тому же принципу, что и у `to_numeric()`:

- корректная дата распознаётся;
- ошибочная запись превращается в `NaT`.

`NaT` для дат играет ту же роль, что `NaN` для чисел.

### 7.2. Важное наблюдение из ноутбука

Сразу после вызова снова проверяется:

```python
df_gameboy.dtypes
```

И мы видим, что `Release date` в исходной таблице всё ещё имеет тип `object`.

### Почему так произошло

Потому что преобразование было выполнено без присваивания результата обратно в столбец.

Чтобы реально изменить тип, нужно писать так:

```python
df_gameboy['Release date'] = pd.to_datetime(
    df_gameboy['Release date'],
    errors='coerce'
)
```

## 8. Повторная проверка структуры таблицы

```python
df_gameboy.info()
```

После добавления столбца `sales_str` таблица уже содержит `7` столбцов:

- `Game`;
- `Developer(s)`;
- `Publisher`;
- `Platform`;
- `Release date`;
- `Sales`;
- `sales_str`.

При этом типы остаются такими:

- `int64` у `Sales`;
- `object` у остальных шести столбцов.

Такой шаг полезен после каждого важного преобразования: он помогает убедиться, что данные действительно изменились так, как мы ожидали.

## 9. Категориальные признаки

### 9.1. Сколько уникальных значений в категориальных столбцах

```python
df_gameboy[['Developer(s)', 'Publisher', 'Platform']].nunique()
```

Результат из ноутбука:

- `Developer(s)` - `31`;
- `Publisher` - `8`;
- `Platform` - `2`.

### Как это интерпретировать

Если столбец содержит ограниченное число повторяющихся значений, его часто выгодно хранить как категориальный.

В нашем примере особенно хорошо подходят:

- `Publisher`;
- `Platform`.

## 10. Преобразование в тип `category`

Сначала в ноутбуке формируется список нужных столбцов:

```python
cat_columns = ['Developer(s)', 'Publisher', 'Platform']
```

Затем выполняется преобразование:

```python
df_gameboy[cat_columns] = df_gameboy[cat_columns].astype('category')
df_gameboy
```

### Что даёт `category`

Категориальный тип полезен для столбцов, где:

- значений немного;
- значения часто повторяются;
- нужно работать с группами, фильтрацией и статистикой по категориям.

### Что изменяется

После преобразования столбцы:

- `Developer(s)`;
- `Publisher`;
- `Platform`

перестают быть обычными строковыми `object` и становятся `category`.

## 11. Проверка результата после преобразования в `category`

```python
df_gameboy.info()
```

По выводу из ноутбука видно:

- `Developer(s)` имеет тип `category`;
- `Publisher` имеет тип `category`;
- `Platform` имеет тип `category`.

Остальные столбцы сохраняют прежний тип:

- `Game` - `object`;
- `Release date` - `object`;
- `Sales` - `int64`;
- `sales_str` - `object`.

### Методический вывод

Не все строковые столбцы нужно переводить в категорию. Например:

- `Game` содержит названия игр и часто используется как обычный текст;
- `Release date` по смыслу лучше переводить не в категорию, а в дату.

## 12. Просмотр списка категорий

```python
df_gameboy['Platform'].cat.categories
```

Результат:

```python
Index(['Game Boy', 'Game Boy Color'], dtype='object')
```

### Что это показывает

У категориального столбца можно явно получить все допустимые значения. Это удобно:

- для проверки данных;
- для построения отчётов;
- для контроля возможных значений признака;
- для подготовки к визуализации или моделированию.

## 13. Краткий обзор использованных методов

### `df.info()`

Показывает структуру таблицы, количество непустых значений и типы столбцов.

### `df.dtypes`

Возвращает типы данных по каждому столбцу.

### `astype()`

Приводит столбец или набор столбцов к нужному типу.

### `pd.to_numeric()`

Преобразует значения в числовой формат и позволяет управлять ошибками.

### `pd.to_datetime()`

Преобразует строковые значения в даты.

### `nunique()`

Считает число уникальных значений.

### `.cat.categories`

Позволяет получить список категорий у столбца типа `category`.

## 14. Что важно запомнить по теме

После изучения темы студент должен понимать следующее:

- типы данных в `pandas` нужно проверять сразу после чтения файла;
- тип `object` часто скрывает обычный текст, даты или "испорченные" числовые значения;
- `astype()` меняет тип данных явно;
- `pd.to_numeric(..., errors='coerce')` помогает находить некорректные числовые значения;
- `pd.to_datetime(..., errors='coerce')` помогает безопасно переводить строки в даты;
- преобразование без присваивания не меняет исходный столбец;
- тип `category` подходит для столбцов с небольшим числом повторяющихся значений.

## 15. Практический смысл темы

Работа с типами данных нужна почти в каждом анализе. Даже если таблица успешно загрузилась, это ещё не означает, что она готова к расчётам. На практике аналитик почти всегда:

1. читает файл;
2. проверяет типы через `info()` и `dtypes`;
3. исправляет строки, которые должны быть числами;
4. переводит даты в формат времени;
5. выделяет категориальные признаки;
6. только после этого переходит к фильтрации, статистике и визуализации.

Если типы заданы корректно, анализ становится надёжнее, а код проще и понятнее.
